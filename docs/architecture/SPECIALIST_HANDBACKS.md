# Specialist handbacks

Sage keeps the Supervisor responsible for the final response. A specialist return supplies findings;
it does not independently certify that the operator's objective succeeded.

## Information returned

The ordinary and explicit return paths in `ai/langgraph/model.py` carry:

1. The specialist's terminal answer, excluding earlier progress narration when a terminal answer exists.
2. Task references whose read calls, results and request provenance match.
3. Bounded response-text observations from those same eligible task-output reads, when available.
4. Fresh output from a supervised task's exactly paired, accepted native execution events.

Read evidence is copied from `get_all_task_output_by_task_id` results rather than generated by another
summarizer. Its existing query also retains the task's callback identity and timestamps; missing fields
remain unknown and conflicting projected metadata is not silently resolved. Command parameters are not
added to this historical read.

Fresh evidence comes from the task adapter's output event only after the runtime matches the current
accepted approval, request, command, callback, parameters and paired start event. An accepted card alone,
an unmatched terminal event, or an exception string is not output evidence. The bounded observation is
separate from the specialist's answer and framed as untrusted data, not embedded in the trusted system
execution context. Instructions within output have no authority. Other tool results, including
credential-store reads, are not added by this path.

Evidence retains its task and request identity, including when a later same-channel report uses it.
Retaining an earlier observation does not establish fresh state or authorize a reread. A read is a partial snapshot: even an untruncated excerpt
does not prove that all task output or every property of the subject was enumerated. Omission/truncation
markers distinguish incomplete excerpts. The supervised context filter is respected; filtered text is
not silently presented as a complete observation. Empty or malformed output supplies no invented evidence.

The Supervisor can reuse one eligible current answer exactly, or synthesize a response when it must combine
findings or correct unsupported claims. Request/worker identity and the answer hash protect reuse fidelity;
they do not establish factual accuracy. The Supervisor prompt asks it to compare task-specific claims with
available observations and preserve uncertainty when evidence is missing or partial.

The runtime also accepts a plain-text Supervisor answer: the graph ends and the streaming path displays
that answer. A missing `respond_to_user` call alone is therefore not a completion failure. The provider
continuation prepares an already-scheduled model call; it does not schedule another call after plain text.
Evaluate terminal delivery separately from whether the answer actually satisfies the request.

An explicit provider `content_filter` finish status is a blocked response, even if it contains text
or tool calls. Sage suppresses that response from answer/tool-card streaming, stops before tool
dispatch, and reports one native error terminal instead of returning an empty successful handback.
The error does not trigger Supervisor redelegation. Ordinary empty replies and text that merely
mentions `content_filter` are not classified as provider filtering.

## Native supervised execution context

The existing runtime-context middleware explains that a guarded tool call opens a native
approval pause. Asking for acceptance in ordinary chat does not create that pause. Only
the exact selection accepted through the native mechanism permits execution.

For the current supervised request, the runtime also projects bounded observations of
native decisions and an accepted selection's matching task lifecycle. These facts come
from validated approval state and the task adapter's observer, separately from the specialist's prose.
They are scoped to the request and operator input revision; stale observations cannot
describe a new instruction to repeat an action.

Rejection means the proposed action did not execute. Redirection rejects that proposal
and supplies a new instruction; an unselected menu option is not a permanent prohibition.
A bare rejection remains binding for its request, while a genuinely new request clears
the previous request's coarse denial guard.

Output classification is not task completion: Mythic's output waiter can return partial
output while a task is pending. An exact task metadata read distinguishes terminal,
pending and unknown state. A terminal task may have failed, and task completion alone
does not establish the intended effect. The Supervisor still assesses the output before
reporting a result or proposing further work. The context does not force a final answer
or suppress legitimate follow-up actions.

## Limits

This is an evidence transport mechanism with model-based assessment, not a deterministic fact checker.
It does not parse domain-specific claims or infer action authorization from source text. It adds no target
actions, evidence-retrieval tool or reviewer agent. Existing native streaming can show specialist prose
before the Supervisor's final response; this mechanism is not pre-display verification.

Offline tests check matching, bounds, source preservation, assembled input and completion behavior.
Real-model replay measures whether the receiver uses the evidence appropriately. These are separate
claims; neither implies live task success or general reliability.

Identity interpretation also requires distinguishing principals from token objects. The specialist's
scope guidance states that equal displayed account names do not establish token equivalence or the
absence of impersonation; explicitly observed active or inactive state remains reportable. Windows
represents token object identity and type separately from the represented principal, and can create
a primary or impersonation token by duplication. See Microsoft's
[TOKEN_STATISTICS documentation](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-token_statistics)
and [DuplicateTokenEx documentation](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-duplicatetokenex).
This is interpretation guidance, not a runtime fact checker or an instruction to issue extra tasks.

## Research informing this design

| Source | Design relevance | Limit of the evidence |
|---|---|---|
| [OpenAI: orchestration and handoffs](https://developers.openai.com/api/docs/guides/agents/orchestration) | Distinguish specialist ownership from manager-owned final answers. | Control ownership does not prove answer correctness. |
| [LangChain: subagent outputs](https://docs.langchain.com/oss/python/langchain/multi-agent/subagents) | Return a concise result with selected state. | A final message may omit evidence retained in the worker's history. |
| [LangGraph Supervisor: message forwarding](https://github.com/langchain-ai/langgraph-supervisor-py#message-forwarding) | Avoid unnecessary paraphrase of a sufficient answer. | A forwarding pattern, not a dependency recommendation or a factual verifier. |
| [Anthropic: multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system) | Preserve source material and artifacts alongside condensed findings. | Results concern that research system, not Sage. |
| [PACT: What Should Agents Say?](https://arxiv.org/abs/2606.05304) | Preserve action, observed state and result in inter-agent communication. | No fixed format wins everywhere; structured content can still be false. |
| [MAST: Why Do Multi-Agent LLM Systems Fail?](https://arxiv.org/abs/2503.13657) | Separate information-transfer, termination and verification failures. | Taxonomy and selected interventions do not establish a universal repair. |
| [Facts Without Rules](https://arxiv.org/abs/2608.29028) | Preserve qualifications and scope as well as operational facts. | Its controlled privacy scenarios do not validate Sage's factual reasoning. |
| [FActScore](https://arxiv.org/abs/2305.14251) | Evaluate supported and unsupported claims separately. | Source-relative factual precision is not objective completion. |
| [ALCE](https://arxiv.org/abs/2305.14627) | Distinguish citations being present from their supporting a claim. | Citation and inference evaluators also make errors. |
| [Chain-of-Verification](https://arxiv.org/abs/2309.11495) | Treat checking a claim as a separate operation from repeating its draft. | An extra model pass alone is not independent evidence. |

The architecture applies the communication and source-access lessons without adopting a new multi-agent
verification framework. Changes should be tested against both incorrect answers and correct answers that
must remain intact.
