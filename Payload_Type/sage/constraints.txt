# Fully-resolved dependency pins for reproducible builds.
#
# requirements.txt declares INTENT — the packages Sage depends on directly. This file records the
# RESOLUTION — every transitive package, at the exact version a green suite was observed against.
# Neither replaces the other: edit requirements.txt to change what Sage depends on, regenerate this
# to record what that resolved to.
#
# Why this exists: a rebuilt venv resolves transitives fresh and can drift many packages from the
# previous resolution without any manifest edit. One such bump (mcp 2.0.0, which removed
# `mcp.server.fastmcp`) breaks every module that reaches ai/mcp.py at collection time. Direct pins
# alone do not bound that.
#
# Use:
#   pip install -r Payload_Type/sage/requirements.txt -c Payload_Type/sage/constraints.txt
#   pip install -r Payload_Type/sage/requirements-dev.txt -c Payload_Type/sage/constraints.txt
# The Dockerfile applies it too, so the image and a developer venv resolve identically.
#
# A constraints file only PINS what gets installed; it never installs anything itself. That is why
# the dev-only entries below are harmless for the runtime image — nothing requires them, so pip
# does not select them.
#
# Regenerate after any intentional dependency change, from a venv whose suite is green:
#   .venv/bin/python -m pip list --format=freeze | grep -v -E '^(pip|setuptools|wheel)==' \
#     > Payload_Type/sage/constraints.txt
# then re-add this header. Record the suite result in the commit message.
